## Live bug: `pending_local_repos` boolean[] cast failure

**Root cause:** `hub/src/db/dal.ts:437-447` in `upsertPendingLocalRepoBatch`. The query:
```sql
SELECT
  unnest(${userIds}::uuid[]),
  unnest(${hostnames}::text[]),
  unnest(${projectDirs}::text[]),
  unnest(${isGit}::boolean[])
```
postgres.js cannot infer `boolean[]` from a JS `boolean[]`. For text/uuid arrays the driver auto-serializes to a PG array literal; for `boolean[]` it serializes the parameter as a scalar (the first element) and Postgres then rejects `cannot cast type boolean to boolean[]`. The text/uuid columns work only because the driver applies its text-array fast path.

**Fix:** use the postgres.js explicit array helper, OR convert booleans to text and cast inside SQL:
- Option A (preferred): `sql.array(isGit, 16 /* PG oid for bool */)` and inline `${sql.array(isGit, 16)}` (no `::boolean[]` suffix needed; oid 16 = bool, 1000 = `_bool`).
- Option B (no helper, portable): map to text `isGit.map(b => b ? 't' : 'f')` and cast `unnest(${isGitTxt}::text[])::boolean`.
- Option C (cleanest, no driver quirks): single-call multi-arg unnest — `unnest($1::uuid[], $2::text[], $3::text[], $4::boolean[]) AS t(uid, host, pdir, isgit)` with `sql.unsafe` + explicit param building.

Recommend Option B for a one-line surgical patch; add a test in `hub/test/supervisor-inventory.test.ts` (new or existing) covering a 2-row batch with mixed true/false.

**Bundle assignment:** Bundle 1 (below).
