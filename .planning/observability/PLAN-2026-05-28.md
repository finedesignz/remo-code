# Observability + QC sweep — 2026-05-28

## North star

When a user reports a problem, we already have the request_id, the structured log trail, and the captured exception in one place — no redeploy, no `console.log` patch, no "can you reproduce." Pre-merge gates catch route-level breakage, schema drift, and test-suite regressions before a PR hits `main`; post-deploy probes confirm the live HTTPS surface is intact within 60s of Coolify finishing. The hub knows it's broken before its users do.

## Inventory of current logging

- `console.log` / `console.error` / `console.warn` raw across `hub/src/**`: **221 call sites** (`grep -c` from batch). No JSON envelope, no level field, no request_id, no user_id, no supervisor_id. Coolify log search is substring-only on free text.
- Hub request lifecycle (`hub/src/index.ts:90` + `90+` middleware chain): no request-id middleware. Hono `c.req.raw` carries no correlation header in or out. Errors that escape route handlers fall through to Hono's default 500 page (no body capture).

- `hub/src/ws/agent.ts` / `client.ts` — auth-reject path logs to `console.warn` with the raw Zod error stringified (`integration-audit`: malformed `subscribe` silently clears subscriptions, no log). WS lifecycle (connect/close/error) is partial console.
- `hub/src/scheduler/dispatcher.ts` — `console.warn` on cost-cap skip; `broadcastScheduledRun` drops events with `status='skipped_quota'` silently because schema doesn't include that enum (`integration-audit`). No counter, no metric, no log on drop.
- `hub/src/error-capture/*` — internal `console.error` on Zod-parse failure of envelopes; the gate decisions (dedupe / rate-limit / cap-exceeded) emit `error_received` WS events but no structured log line per gate.
- Supervisor (`supervisor/src/index.ts:34`): `setupFileLogging` tees stdout/stderr to a per-day file via `fs.createWriteStream` — but stream is never closed on `SIGINT`/`SIGTERM` (up to 64 KB pending lines lost — `supervisor-audit`). `supervisor/src/hub-client.ts` logs reconnect/auth with `console.log` only; `ws.onerror` is **silent** (`hub-client.ts:117-119`). No correlation between supervisor logs and hub run rows.
- Web (`web/src/**`): NO error capture. Browser console errors die on the client. User screenshots are the only signal (this session's repeated failure mode).
- Tauri sidecar (`supervisor/tauri/src-tauri/src/*.rs`) — Rust `println!` only; no tracing, no ship-out.

**Request_id story today: none.** A hub request → WS dispatch → supervisor spawn → CLI run → assistant_message persist has zero common identifier traversable in logs.

## Gaps + risks (ranked by blast radius)

1. **Web SPA throws are invisible to the hub.** `web/src/**` has no `window.onerror`, no `unhandledrejection`, no React error boundary that reports. Every Phase 06/07/08 UI regression this session was first detected by the user pasting a console screenshot. Largest blast radius: every user-facing bug today is "find out from user." File anchor: `web/src/App.tsx` (no boundary), `web/src/main.tsx` (no global hook).

2. **Hub exceptions in `void`-fire dispatch paths are silently swallowed.** `coolify-webhook.ts:212` (`void dispatchTriage(...).catch(...)`), `hub/src/error-capture/dispatcher.ts` (grace replay), the scheduler dispatcher's `setImmediate` chains. A Postgres CHECK violation (the `task_type='triage'` bug — `integration-audit` Critical) raised 23514 with **zero log output**. Coolify search showed no entry. File anchors: `hub/src/api/coolify-webhook.ts:212`, `hub/src/scheduler/dispatcher.ts`, `hub/src/error-capture/grace.ts:43`.

3. **Health probe returns 200 while DB/Redis/Titanium are down.** `hub/src/index.ts:90` doesn't touch deps. A Postgres restart during deploy → process stays "healthy" → Coolify rolls forward → first user request 500s. File anchor: `hub/src/index.ts:90`.

4. **No request_id traversable across hub→supervisor→CLI.** When `session_runs` zombies pin the cap (sessions-audit Critical), there's no way to grep from the user's failing send_message back through the dispatcher to the supervisor exit. File anchors: `hub/src/index.ts` (no middleware), `hub/src/ws/agent.ts`, `supervisor/src/hub-client.ts`.

5. **CI does not run `bun test`.** Phase 08 drift (8 fails → 35 fails over 30 min from `mock.module` pollution — `feedback_bun_mock_pollution.md`) merged because no gate ran the full suite. File anchor: `.github/workflows/` (no test job).

6. **No post-deploy smoke.** `feedback_https_url_smoke.md` enumerates 14 endpoints that must 200/401 after every deploy. Manual curl only. The `/api/supervisors/:id/scan` 502 (Bun `idleTimeout`) and `/api/account/coolify-webhook-secret` 500 (missing DAL helper) both shipped to prod because the human forgot to probe.

7. **Supervisor reconnect storms are undiagnosable.** Tauri tray surfaces no last-error / last-reconnect. `hub-client.ts:117-119` swallows `ws.onerror`. When the supervisor can't auth (the `cli_kind` / `rootless_session_ids` schema drift — `project_handoff_supervisor_ws_close.md`), the user sees "offline" with no reason. File anchors: `supervisor/src/hub-client.ts:84,117`, `supervisor/tauri/src-tauri/src/main.rs`.

8. **Cost-cap drops are silent past the dispatcher.** `dispatcher.ts` emits `status:'skipped_quota'` not in the schema enum; `registry.ts:99` drops the broadcast with a `console.warn` (`integration-audit` Medium). Web UI never sees the lifecycle event. No counter. File anchors: `hub/src/scheduler/dispatcher.ts:133`, `hub/src/ws/registry.ts:99`.

## Out-of-scope

- **No new third-party logging dep** (pino, winston, OpenTelemetry SDK). The 60-line helper is enough; revisit only when log volume forces structured-ingest cost calculation.
- **No distributed tracing** (W3C `traceparent`, span propagation). Request_id correlation only this round.
- **No log shipping to a hosted sink** (Loki, Datadog, Honeycomb). Coolify ingests stdout; structured JSON makes grep-search functional. Pick a sink only after we have 30 days of structured data to evaluate.
- **No bulk `console.*` → logger migration** beyond the 25 nominated sites. Drive-by sweep would balloon B1.
- **No alerting rules** (PagerDuty, Prometheus Alertmanager). Metrics first; rules after we have a week of baseline.
- **No retry/backoff for error-intake POSTs from web** — fire-and-forget; if the hub is down for a browser-side error, accept the loss.
- **No supervisor → hub log streaming.** Per-day file + crash-only intake. Streaming requires backpressure design; defer.
- **No Tauri tray "view full logs" window.** Tray dot + last-error line only.
- **No fix for the in-flight bugs themselves** — bundles 1-7 in TRIAGE-2026-05-28.md own those. This sweep adds the **signals** that would have caught them.
