1. **CRITICAL — [proof-guard.ts:174](C:/Users/artic/GitHub/remo-code-ptycap05/hub/src/orchestrator/proof-guard.ts:174)**  
   **Evidence:** With proof mode enabled, a task without its own proof row returns `pass_through`. The global due-scan selects every enabled orchestrator task ([controller.ts:699](C:/Users/artic/GitHub/remo-code-ptycap05/hub/src/orchestrator/controller.ts:699)), while the repo allowlist is checked only for offline autospawn ([inject.ts:267](C:/Users/artic/GitHub/remo-code-ptycap05/hub/src/orchestrator/inject.ts:267), [inject.ts:368](C:/Users/artic/GitHub/remo-code-ptycap05/hub/src/orchestrator/inject.ts:368)). Therefore any other enabled task with an online session receives the ordinary merge/deploy-capable dev prompt when the runbook turns the global flags on. The test at [orchestrator-proof-tracer.test.ts:288](C:/Users/artic/GitHub/remo-code-ptycap05/hub/test/orchestrator-proof-tracer.test.ts:288) explicitly codifies this unsafe pass-through.  
   **Fix:** Arm and enable must refuse while any other orchestrator task is enabled, across all users because the flags are global. Add a runtime exclusivity check so proof mode scans/dispatches only the claimed proof task.

2. **CRITICAL — [orchestrator-proof-dal.ts:143](C:/Users/artic/GitHub/remo-code-ptycap05/hub/src/db/orchestrator-proof-dal.ts:143)**  
   **Evidence:** Arming reuses and disables an existing `dev` task but neither cancels an already-running cycle nor invalidates queued/grace dispatch requests. Those requests preserve their original prompt ([pipeline.ts:269](C:/Users/artic/GitHub/remo-code-ptycap05/hub/src/dispatch/pipeline.ts:269), [pipeline.ts:334](C:/Users/artic/GitHub/remo-code-ptycap05/hub/src/dispatch/pipeline.ts:334)). Once a proof row exists, its gate authenticates only the reusable `task:<taskId>` counter key ([proof-gates.ts:81](C:/Users/artic/GitHub/remo-code-ptycap05/hub/src/orchestrator/proof-gates.ts:81)); it does not require the request to identify the new proof run or contain the proof prompt. A pre-arm dev prompt can therefore be replayed and authorized as proof traffic. The “final injected string” test only records a mocked `inject` argument ([orchestrator-proof-cycle.test.ts:160](C:/Users/artic/GitHub/remo-code-ptycap05/hub/test/orchestrator-proof-cycle.test.ts:160)); it never exercises queue/grace replay or the actual send.  
   **Fix:** Put a server-only `proofRunId` on proof dispatch requests and require an exact active-run match in the final gate. Arm must also halt the session and cancel pending routine cycles before reusing the task. Add a test that queues an ordinary dev prompt before arm and proves it can never reach `send`.

3. **MAJOR — [proof-arm.ts:304](C:/Users/artic/GitHub/remo-code-ptycap05/hub/src/orchestrator/proof-arm.ts:304)**  
   **Evidence:** Disarm commits the terminal/disabled state first and engages the kill switch afterward. A dispatch that already passed the proof gates can run the pipeline’s final halt check before the kill-switch write commits, then send at [pipeline.ts:416](C:/Users/artic/GitHub/remo-code-ptycap05/hub/src/dispatch/pipeline.ts:416); that final check rereads only the kill switch, not proof status. The test at [orchestrator-proof-disarm.test.ts:28](C:/Users/artic/GitHub/remo-code-ptycap05/hub/test/orchestrator-proof-disarm.test.ts:28) asserts call order but does not race disarm against dispatch.  
   **Fix:** Engage the session kill switch before disarm, or write the kill row and terminal transition atomically. Also recheck active proof-run identity immediately before `send`.

4. **MAJOR — [token-usage-dal.ts:250](C:/Users/artic/GitHub/remo-code-ptycap05/hub/src/db/token-usage-dal.ts:250)**  
   **Evidence:** The “hard” token budget sums whatever `token_usage` rows happen to exist and treats attribution as sound whenever the session row still exists. But usage persistence failures are merely logged and discarded at [agent.ts:837](C:/Users/artic/GitHub/remo-code-ptycap05/hub/src/ws/agent.ts:837). After a transient insert failure and DB recovery, the proof gate sees a live session and an undercounted total, allowing further turns. The deletion test covers only `sessionExists=false`, not a missing usage row for a live session.  
   **Fix:** Durably associate every proof dispatch with an expected usage record/proof-run ID. A completed proof turn without persisted usage must terminalize as `budget_attribution_lost`; usage events need retry/ack or a durable outbox.

5. **MAJOR — [proof-github.ts:121](C:/Users/artic/GitHub/remo-code-ptycap05/hub/src/orchestrator/proof-github.ts:121)**  
   **Evidence:** The adapter discards every PR whose head does not start with `proof/` at line 128, before the verifier can enforce scope. `PullSummary` also omits head-repository and author identity. Consequently an off-prefix PR is invisible, while a fork PR using the exact `proof/<run-id>` branch name can be accepted and reported `pr_open_green`. Existing tests only feed the verifier already-filtered proof heads.  
   **Fix:** Return all relevant PRs with `head.repo.full_name`, author, and creation time. Require the successful PR’s head repository to equal the armed repository, and treat new agent-authored off-prefix PRs as `pr_scope_violation`.

6. **MAJOR — [proof-arm.ts:155](C:/Users/artic/GitHub/remo-code-ptycap05/hub/src/orchestrator/proof-arm.ts:155)**  
   **Evidence:** Repository identity is lowercased only for installation lookup, then the caller’s original casing is stored. Both the active-repo unique index and merge refusal use case-sensitive equality ([schema.sql:1733](C:/Users/artic/GitHub/remo-code-ptycap05/hub/src/db/schema.sql:1733), [orchestrator-proof-dal.ts:270](C:/Users/artic/GitHub/remo-code-ptycap05/hub/src/db/orchestrator-proof-dal.ts:270)). GitHub owner/repository path names are case-insensitive, so `github://Owner/Repo` and `github://owner/repo` can represent the same physical repository while bypassing single-flight and merge lookup. [GitHub’s REST documentation](https://docs.github.com/en/rest/repos/rules?apiVersion=2026-03-10) confirms owner and repository path names are not case-sensitive.  
   **Fix:** Canonicalize GitHub owner/repository identities before session comparison, allowlist insertion, proof storage, and lookup. Enforce the partial unique index over the canonical value.
