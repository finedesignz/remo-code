<objective>
Wire ONE live PTY turn's token spend end-to-end into the usage ledger, tagged as
interactive: supervisor tails the interactive CLI's own on-disk transcript JSONL,
extracts the four token buckets per assistant record, pushes the existing
`usage_event` frame additively tagged `runner_type: 'pty-interactive'`, and the hub
persists it into a new `token_usage.runner_type` column.

Purpose: today a PTY turn's spend is not merely post-hoc-delayed, it is **completely
invisible** — `token_usage` records zero rows for `runner_type='pty-interactive'`
sessions, forever. Phase 2 cannot gate a number that does not exist. This plan makes
the number exist, live.

Output: a production-quality vertical slice through every layer the phase touches
(supervisor fs tail → supervisor emitter → WS frame → hub zod → hub handler → hub DAL
→ Postgres column), proven by a real growing-file integration test.

RECORD/OBSERVE ONLY. This plan adds no gate, no block, no deny, no new `gates: [...]`
array, and no new dispatch call site.
</objective>

  <behavior>
Contract the new supervisor test asserts (these are the acceptance behaviors, not a suggestion):
- Appending an assistant record carrying `message.usage` to a transcript file that is ALREADY being tailed produces exactly one emitted frame, while the file is still open and no exit/kill has occurred (SC-1).
- The emitted frame's `type` is `usage_event`, its `runner_type` is `pty-interactive`, its `cost_source` is `estimated`, its `cost_usd` is `0`, and its four token bucket fields carry the record's `input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens` verbatim.
- `model` is taken from `message.model` when it is a string, else `null`.
- A record whose `type` is not `assistant`, or which has no `message.usage`, emits nothing.
- A record whose four buckets are all zero emits nothing (no noise rows).
- A syntactically invalid JSON line emits nothing AND does not stop the tailer: a valid usage record appended AFTER the bad line still emits.
- Appending the SAME record (same `uuid`) twice emits once.
- After the tail's byte offset is reset by a truncation (file rewritten shorter), previously-seen `uuid`s are not re-emitted.
- `stop()` is idempotent and no frame is emitted after it.
- A codex-backed session (`cliKind` 'codex') emits nothing at all and starts no watcher.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| interactive CLI → supervisor filesystem | The `claude` TUI writes a JSONL transcript the supervisor did not author and cannot validate ahead of time; a buggy or compromised CLI release could emit a malformed or hostile line. |
