## 0. One-paragraph verdict

remo-code already has ~80% of a dispatcher, but it is shaped as a **per-session heartbeat** (one `orchestrator` scheduled task bound to ONE existing session, which re-injects a "macro prompt" that makes the agent read its own `.planning/STATE.md` and continue), NOT a **cross-repo backlog scheduler**. There is no backlog table, no repo-priority queue, no per-account/token selection, no PR-merged/CI event inbound, and the supervisor never creates worktrees. CORCH = (a) a new backlog/work-item layer that picks a repo, (b) uses the existing governed launch + dispatch chain to get a prompt into a session in that repo, (c) reuses the existing caps/kill-switch/ledger, (d) adds an inbound AAF webhook and an account-aware quota source.

## 5. Scheduler quota-skip
